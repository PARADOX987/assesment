# Review (Part A)

## Starter code review

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Naive/local timestamps and `replace()` on the punch-in date do not handle UTC input or an overnight shift's start day. | Punch an overnight shift at 05:30 IST; the shift belongs to yesterday, not today's 22:00 start. | Normalize instants to UTC, convert to IST, and compare against shift start on the attendance date. |
| 2 | `compute_work_hours` | Python `round()` uses ties-to-even rather than the required half-up rounding. | A duration whose hour value is exactly halfway between hundredths can round the wrong way. | Use `Decimal` with `ROUND_HALF_UP`. |
| 3 | `compute_overtime` | Always places shift end on the attendance date and therefore miscalculates overnight shifts; it also has no explicit 30-minute threshold. | The sample 22:00-06:00 shift ending at 06:40 should report 40 overtime minutes. | Place overnight shift end on the next IST day and apply the >=30-minute threshold. |
| 4 | `health` | Always reports readiness without checking MongoDB. | Stop MongoDB and `GET /health` still returns 200. | Ping MongoDB and return 503 on a database error. |
| 5 | `create_employee` | A check-then-insert duplicate test races under concurrent requests; no unique index is created. | Send simultaneous requests with the same `emp_code`; both can be inserted. | Create a unique index at startup and translate `DuplicateKeyError` to 409. |
| 6 | `create_employee` / `EmployeeIn` | Request fields and date/time formats are not validated against the contract. | Try an invalid employee code, email, date, shift time, or identical shift times. | Add Pydantic constraints and date/shift validation. |
| 7 | `create_employee` | `created_at` is naive, and response values do not convert BSON datetimes to epoch milliseconds. | Inspect the stored timezone or response for `created_at`. | Store aware UTC datetimes and serialize instants as epoch milliseconds. |
| 8 | `list_employees` | The first page skips `page_size` records, and `total` counts the unfiltered collection. | With page 1 and a department filter, the first item is skipped and `total` ignores the filter. | Use `(page - 1) * page_size`; count with the same filter. |
| 9 | `list_employees` | Page inputs are not bounded and the query has no explicit sort. | Request page 0, page size >100, or repeat a page across database plans. | Validate pagination and sort by `emp_code` ascending. |
| 10 | `punch_in` | Unknown employees cause a `KeyError` and 500 instead of 404. | Punch in using an unknown `emp_code`. | Check employee existence and return 404. |
| 11 | `punch_in` | Epoch milliseconds are interpreted in the machine's local timezone, and the attendance date ignores IST and overnight rules. | Use a UTC instant near midnight or the overnight-shift sample. | Validate epoch milliseconds, truncate to seconds, convert to IST, and calculate R1's attendance date. |
| 12 | `punch_in` | A falsey timestamp such as zero is silently replaced with the current time; floats, strings and seconds are not contract-validated. | Send `punched_at: 0`, seconds, a float, or a string. | Use strict integer/range validation and distinguish omitted from supplied values. |
| 13 | `punch_in` | The existence check followed by insert is not atomic, so concurrent punches can create duplicates. | Send parallel punches for one employee and attendance date. | Enforce the unique (`emp_code`, `date`) index and map duplicate-key errors to 409. |
| 14 | `punch_in` | The status is unrestricted, derived values do not fully follow R1-R2, and the response exposes an `id` that the contract forbids. | Send `ABSENT`, test a 09:40:01 punch, or inspect the response keys. | Restrict status, compute values with the rules, and serialize only contract fields. |
| 15 | `list_attendance` | It loads and sorts the entire matching collection in Python. | Run it against the 100,000-record dataset; memory and latency scale with all matches. | Apply filters, deterministic sort, skip/limit and count in MongoDB. |
| 16 | `list_attendance` | It does not validate the date range, and ties on date have no required employee-code ordering. | Reverse `date_from`/`date_to`, or list records with the same date. | Validate the inclusive range and sort by date descending, then `emp_code` ascending. |
| 17 | `list_attendance` | The response leaks MongoDB `_id` as an `id` field and does not normalize BSON timestamps or legacy missing fields. | Inspect an attendance response containing a punch time or missing `history`. | Serialize only contract fields, translate instants, and default legacy derived/history values. |
| 18 | Application startup / indexes | No indexes are created for unique keys, attendance filters, sorting, or analytics joins. | Inspect collection indexes or explain a large list query. | Create idempotent unique and query-supporting indexes during startup. |
| 19 | Remaining endpoints | Punch-out, correction, analytics aggregation, and explain endpoints are absent. | Request any endpoint marked “You” in the assignment. | Implement all contract endpoints, including MongoDB pipelines and execution-stat explain output. |

**Checked and not defects:** the starter's page size and default page size match the contract; its attendance date range comparisons are inclusive; and its late helper uses a strict greater-than-10-minute grace check and measures from shift start for an ordinary same-day shift. The helper still needed changes for timezone and overnight behavior.
